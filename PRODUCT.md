# Product

## Register

product

## Users

Jaull is for people evaluating and running local AI models on real machines: developers, technical students, infra-minded users, and local-AI operators who need to understand hardware fit, runtime options, and measured behavior without memorizing every GGUF quantization or runtime flag.

## Product Purpose

Jaull helps users decide what model can run locally, why that recommendation was made, how it can be executed, and what happens when it is validated or benchmarked. Success means the user can move from recommendation to execution path to run, validation, benchmark, and comparison without needing to decode implementation details first.

## Brand Personality

Clear, technical, restrained. Jaull should feel like a trustworthy instrument: calm under complexity, explicit about uncertainty, and direct about evidence.

## Anti-references

Avoid marketing-style hero layouts, decorative dashboards, over-explained technical jargon in primary screens, flat dumps of every artifact variant as equal choices, and benchmark views that foreground methodology IDs, device IDs, repetitions, or build hashes before user-meaningful results.

## Design Principles

- Show the selected plan consistently: every header, action, result, and comparison must describe the execution path actually being used.
- Separate choices from details: primary screens explain model, runtime, artifact, readiness, performance, and evidence; technical details keep raw backend and reproducibility fields.
- Group variants by decision: quantizations belong under a llama.cpp execution option, not as dozens of peer paths.
- Evidence earns prominence: distinguish estimated-only, validated, and benchmarked states without implying that one artifact/runtime is universally better.
- Keep expert power available: advanced details should be one action away, never removed.

## Accessibility & Inclusion

Use readable contrast in terminal themes, avoid relying on color alone for status, keep labels plain-language, and preserve keyboard-first navigation. Motion is minimal and state-based because the primary interface is a terminal workflow.
