# Task T7: Balanced should prefer a comfortable quantization to a tight one

To choose a GGUF quantization for a model, Jaull walks a ladder of quantizations ordered by the
user's priority and takes the first one that fits the detected memory
(`_select_gguf` in `src/jaull/estimator/configuration.py`). "Fits" includes the status TIGHT, which
leaves very little headroom.

For the Balanced priority this is the wrong trade: if Q5_K_M is TIGHT and the next reasonable rung,
Q4_K_M, is COMFORTABLE, Balanced should take Q4_K_M. Expected behaviour:

- Balanced: a TIGHT rung that is not an aggressive quantization is remembered, and the ladder goes on.
  If a later reasonable rung fits with more headroom, that one is chosen. If none does, the remembered
  tight rung is chosen after all, with a warning that says it is a tight fit.
- A rung that fits comfortably first is still chosen as today, with no warning.
- The Quality priority keeps today's behaviour: the best quantization that fits, even when tight.
- Aggressive quantizations keep their existing warning.

The new test below reproduces the problem and currently fails:

    uv run pytest tests/test_recommendation_configuration.py

Make it pass without breaking the rest of the test suite (`uv run pytest`).
