# Task T3: a stray "gguf" tag turns a packed checkpoint into a GGUF build

During a real search on an Intel Arc B60 (Vulkan only, no CUDA), a model published as a
compressed-tensors (AWQ) checkpoint also carried a `gguf` tag on Hugging Face. Candidate
preselection (`src/jaull/discovery/candidate_filter.py`) treated it as a 4-bit GGUF build that fits
the card, so it took one of the few exploration slots, and was only rejected later at inspection
because its loader needs CUDA.

A repository whose name says GGUF is a GGUF build, whatever else it tags (GGUF repositories tag every
precision they offer). A repository that only says GGUF in a tag, while also tagging a packed
Transformers format (`awq`, `gptq`, `compressed-tensors`), is that packed checkpoint, not a GGUF
build. A GGUF tag without any packed format still means GGUF.

The new tests below reproduce the problem; at least one currently fails:

    uv run pytest tests/test_discovery_search.py

Make them pass without breaking the rest of the test suite (`uv run pytest`).
