# Task T6: the estimator's batch size is passed to llama.cpp as a token batch

`InferenceConfiguration.batch_size` in Jaull's estimator means the number of independent sequences
in a batch, each keeping its own context and KV cache. That is what the memory estimate multiplies.
`concurrent_users` is a separate axis that also multiplies the KV cache.

llama.cpp's `--batch-size` (`-b`) is something else: the number of prompt tokens submitted per
decode call. Today the llama.cpp adapter (`src/jaull/runtime/llama_cpp.py`) turns the estimator's
`batch_size` into `--batch-size`, so a plan sized for one sequence launches llama.cpp with
`--batch-size 1`, a one-token prompt batch.

Generated plans must not emit `--batch-size` (nor `--ubatch-size`) from the estimate; the prompt-token
batch is left to the llama.cpp runtime default, and the recommendation's reasons must say so. Building
the recommendation must not modify the estimate. Make the meaning of `batch_size` clear where it is
defined.

The new and updated tests currently fail:

    uv run pytest tests/test_runtime_llama_cpp.py tests/test_llama_cpp_runner_execution.py tests/test_execution_planner.py

Make them pass without breaking the rest of the test suite (`uv run pytest`).
