# Task T4: a GGUF quantization published whole and in parts is counted twice

Several Hugging Face repositories (Qwen's among them) publish each GGUF quantization twice: as one
file, `name.gguf`, and as split parts, `name-00001-of-0000N.gguf` ... `name-0000N-of-0000N.gguf`.
They are the same weights. Jaull groups the files of a repository by quantization
(`src/jaull/huggingface/classifiers.py`) and sums every file in the group, so the weights are counted
twice: a 7B model in Q8_0 is estimated at about 15 GiB instead of 7.5, and the download would fetch
both copies.

When a quantization exists both whole and in parts, keep only the whole file. Parts that are all a
repository has for a name must still be kept and added up, and a quantization published as one
file only must not change.

Note that Jaull caches repository analyses on disk; think about whether entries written with the old
behaviour could still be served.

The new test below reproduces the problem and currently fails:

    uv run pytest tests/test_repository_classifier.py

Make it pass without breaking the rest of the test suite (`uv run pytest`).

Rules: do not modify, add or delete anything under `tests/`. Change only the application code.
