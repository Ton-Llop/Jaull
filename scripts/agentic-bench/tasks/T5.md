# Task T5: the Benchmark "Memory" tab compares host RAM with a VRAM estimate

In the TUI, the Memory tab of the Benchmark screen (`src/jaull/tui/screens/recommendation_benchmark.py`)
shows the memory estimate next to what was measured. On an Intel Arc B60 under WSL2 it printed:
5.76 GiB of process RAM measured against a 20.74 GiB estimate, "Difference: -72 %". The model's
weights were on the GPU, so the process RAM says nothing about the GPU estimate, and that difference
is meaningless.

Expected behaviour:

- When the plan places the weights on the GPU, RAM and VRAM are two separate pools and are never
  compared with each other. Show the peak RAM of each run, then the estimated VRAM, then the measured
  VRAM when a reading exists (and only then the difference between the two VRAM figures). When there
  is no VRAM reading, say so instead of showing a number.
- When the model is partly offloaded to RAM, also show the host-RAM share of the estimate.
- A CPU-only run keeps comparing the RAM estimate with the measured RAM, as today.

The exact labels the screen must use are in the new tests. They currently fail:

    uv run pytest tests/test_tui_benchmark.py tests/test_memory_estimator.py

Make them pass without breaking the rest of the test suite (`uv run pytest`).

Rules: do not modify, add or delete anything under `tests/`. Change only the application code.
