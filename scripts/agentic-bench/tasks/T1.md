# Task T1: one unstorable file hides every execution path of a model

On a machine with an Intel Arc B60, Qwen3.8-27B publishes its BF16 weights as split parts inside a
folder of the repository (`BF16/Qwen3.8-27B-BF16-00001-of-00002.gguf`). When Jaull asks whether that
file is already stored locally, `ArtifactStorage.exists()` raises "Filename must be a single basename".
The exception propagates, and the user sees no execution path at all for the model, not even for
the quantizations that are perfectly storable.

Asking whether a file is stored must simply answer "no" for a name this storage cannot hold
(a file inside a folder, an absolute path, a path traversal). Building a path to write to must keep
refusing those names, so nothing outside the storage root can ever be reached.

The new test below reproduces the problem and currently fails:

    uv run pytest tests/test_artifact_storage.py

Make it pass without breaking the rest of the test suite (`uv run pytest`).

Rules: do not modify, add or delete anything under `tests/`. Change only the application code.
